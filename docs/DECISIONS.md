# Decisions

Decisions taken during development that ROADMAP.md does not cover, one line each: date, decision, reason.


- 2026-10-14 — SUMMARY.md order is Filesystem, Disk, Permissions, Processes & scheduling, Memory, Finding and transforming. Filesystem and Permissions have no cards yet. — The phase 0 acceptance (`idk 5.1`) and the TUI mockup put Memory at chapter 5; the section 6 example would make it 3.
- 2026-10-14 — In SUMMARY.md, a hub can only be a chapter page and a card can only be an entry under a chapter; the titles in SUMMARY.md must match the frontmatter titles. — Stops the TOC and the cards from drifting apart.
- 2026-10-14 — `probes::REGISTRY` lists probe names (with no functions) from phase 0. — The 6.3 validation must check probe names before the probes exist; the functions come in phase 1.
- 2026-10-14 — Kept `serde_yaml` 0.9 although it is deprecated upstream. — The roadmap names it and it works. Switch to a maintained fork if it causes trouble.
- 2026-10-14 — Content uses fenced code blocks (```), never indented ones. — In CommonMark, an indented block right after a list becomes a paragraph of the last list item.
- 2026-10-14 — TL;DR length = non-blank source lines, code fences excluded. — Close to what the screen shows, and cheap to check.
- 2026-10-14 — Validation beyond 6.3: unknown frontmatter fields are errors, and an alias can't be a subcommand name (`toc`, `search`…) or look like a chapter number. — Catches typos and keys that could never be reached.
- 2026-10-14 — `idk 5` (a bare chapter number) opens that chapter's hub when it has one, and otherwise matches nothing. — Natural extension of resolution step 3.
- 2026-10-14 — The no-match message suggests `idk toc` until `search` and `ask` exist. — Never point users to a command that isn't there yet.
- 2026-10-14 — Exit code 3 = internal error (invalid embedded content, failed write to stdout); a closed pipe is not an error. — 0/1/2 are taken by success, no match and usage error.
- 2026-10-14 — `build.rs` with `rerun-if-changed=content`. — `include_dir!` does not see new files without it.
- 2026-10-14 — A hub page lists its own chapter's cards first, then its `cards` field. — Otherwise the Memory hub would not link to 5.1.
- 2026-10-14 — Text width = number of chars, without `unicode-width`. — Content is mostly ASCII; avoids a dependency.
- 2026-10-14 — Added `libc` for `statvfs` (one small `unsafe` call). — std has no statvfs; `nix` or `rustix` would be much bigger for a single call.
- 2026-10-14 — Added `serde_json` (JSON output) and `insta` (snapshots, dev only). — Both listed in section 4.
- 2026-10-14 — `ProbeCtx` takes filesystem space from a fixed table in tests instead of statvfs. — statvfs on a fixture dir would return the host's numbers, and snapshots would change from machine to machine.
- 2026-10-14 — `disk.tree` matches mounts by device number, or else by source path (`/dev/vdb1`, `/dev/mapper/NAME`). — btrfs subvolumes report an anonymous device number (0:NN), as on the dev VM.
- 2026-10-14 — `disk.tree` hides loop and ram devices and devices of size 0, and says how many it hid. — Snaps and container tools create dozens of them.
- 2026-10-14 — buff/cache = Buffers + Cached + SReclaimable. — Same formula as procps-ng `free`; checked against `free -k` on the dev VM.
- 2026-10-14 — Rotational disks are shown as "rotational", not "HDD". — Virtual disks often report rotational=1; "HDD" would be wrong there.
- 2026-10-14 — Fuzzy matching: edit distance with transpositions on ids, aliases and titles; allowed distance 1 (≤4 letters), 2 (≤8), 3 beyond, plus typed prefixes; nothing under 3 letters. The closest page is shown with a note. — `memroy` → Memory, while a random short word doesn't open a random page.
- 2026-10-14 — When nothing matches, the suggestions come from `search` (which tolerates one typo in words of 5+ letters). — `idk swapiness` then points to Memory and 5.1.
- 2026-10-14 — `--json` works on every command (`toc`, `search`, `probe`), not only on queries. — Cheap, and the MCP server (phase 4) needs the same structures.
- 2026-10-14 — `idk probe` without a name lists the probes. `idk search` without a match exits with 1, like a query. — Discoverability; consistent exit codes.
- 2026-10-14 — `view::Lookup` (query, match kind, entry, suggestions, probe results) is the view model shared by text, JSON and later surfaces. — Section 5 data flow.
- 2026-10-14 — Pages are built as a `render::Doc` (lines of styled spans, some with an `Open` or `Toggle` action); the CLI turns it into ANSI text, the TUI into widgets plus click regions. — The only way to share the renderer without duplicating it (phase 2 criterion). All CLI snapshots stayed byte-for-byte identical through the change.
- 2026-10-14 — `ratatui` 0.30 without default features (`crossterm` only), and crossterm through `ratatui::crossterm`. — Fewer dependencies, and one crossterm version.
- 2026-10-14 — TUI keys: ↑↓/jk move or scroll, ←→/hl switch pane, Tab/Shift-Tab go from link to link, Enter opens, Backspace goes back, `/` search, `?` prompt, `r` refresh, `M` mouse, `q` quits, Esc closes an overlay or quits. — The roadmap mockup gives j/k, enter, /, r, ?; Tab for links works like a browser.
- 2026-10-14 — In the TUI, deep dive questions show collapsed (▸); opening one scrolls it to the top of the pane. — Otherwise a question at the bottom opens off screen.
- 2026-10-14 — The TUI's left column adapts: tables put a long command on its own line when the pane is narrow (`MAX_LEFT` = min(30, width/3)). — At 80×24 the content pane is 52 columns; CLI output is unchanged.
- 2026-10-14 — `idk` alone opens the TUI only when stdin and stdout are terminals; otherwise it prints the help and exits with 2. — Scripts and pipes keep the phase 0 behaviour.
- 2026-10-14 — `idk ask` builds the prompt even when nothing matches (system data only) and says so on stderr. The arch comes from the build target (`std::env::consts::ARCH`). — A question without a card is still worth asking.
- 2026-10-14 — `--redact` replaces the home directory with `~`, any other `/home/NAME` with `/home/<user>`, and the hostname and username (whole words only) with `<hostname>` / `<user>`. It applies to the whole prompt, the user's question included. — Probe data (mount points, process names) and the question can both leak them.
- 2026-10-14 — The TUI's `?` shows the prompt for the current page without redaction; `M` frees the mouse to select it. — No clipboard access without a new dependency.
- 2026-10-14 — Phases 2 and 3 are one commit. — The TUI's `?` key (phase 3) and the prompt builder were written together.
- 2026-10-14 — MCP with `rmcp` 3.5 (features `server`, `transport-io`, `macros`) and `tokio` on a single-thread runtime, started only by `idk mcp`. — Section 4 names rmcp; the rest of `idk` stays synchronous.
- 2026-10-14 — Every MCP tool returns its JSON as text content, with the same shapes as `--json` (`view::Lookup`, search hits, `ProbeResult`). — One structure per answer whatever the surface.
- 2026-10-14 — MCP: `lookup` with no match is a normal result (`"match": "none"` plus suggestions); an unknown probe name is a tool error (`isError`) that lists the valid names. — An agent can recover from both without a protocol error.
- 2026-10-14 — Every tool carries `readOnlyHint: true` and `openWorldHint: false`, and its description says "Read-only". — Section 8.4: the server must state that it never modifies the system.
- 2026-10-14 — `idk toc --json` now prints `view::Toc` (hubs, then chapters with card references) instead of the raw `Chapter` list. — Same output as the MCP `toc` tool, and the cards come with titles.
- 2026-10-14 — New chapters go after the existing ones (7 CPU, 8 Network, 9 Boot), and new cards after the existing cards of their chapter. — Chapter numbers are addresses people type (`idk 5.1`): adding content must not renumber what exists.
- 2026-10-14 — Seven new probes: `cpu.summary`, `net.interfaces`, `net.listening`, `net.dns`, `boot.info`, `user.identity`, `fs.tmp`. — Each answers the question of a new card or hub on the machine (phase 5 rule).
- 2026-10-14 — IP addresses come from `getifaddrs` (libc), replaced by a fixed list in tests like `statvfs`; no file in /proc lists IPv4 addresses per interface. — Without them the network hub would miss its main answer.
- 2026-10-14 — `net.listening` finds a socket's process through /proc/PID/fd links, so other users' processes show only as root; the note points to `sudo ss -tulpn`. — Read-only, no external binary, honest about the limit.
- 2026-10-14 — Firmware is reported as UEFI (/sys/firmware/efi), device tree (ARM boards and VMs) or BIOS; Secure Boot comes from the SecureBoot EFI variable (fifth byte). — The dev VM is ARM with a device tree: "BIOS" would have been wrong there.
- 2026-10-14 — `FsSpace` now carries inodes (statvfs `f_files`/`f_ffree`); the disk table shows inode use when the filesystem counts inodes (not btrfs). — Needed by the "Links, inodes and disk full" card.
- 2026-10-14 — The live block's label column is 10 wide instead of 9. — "Firmware" and "Governor" left a single space before their value.
- 2026-10-14 — Word wrap cuts a non-code word longer than a whole line (a kernel command line token on the dev VM was 88 characters); code is still never cut. — Keeps the 80-column rule on real machines.
- 2026-10-14 — Search excerpts prefer the card's text (TL;DR, pitfalls, deep dive) over its commands and paths fields. — "swapon vmstat" told less than the TL;DR line.
- 2026-10-14 — The command cards (6.2 to 6.9) have no probe. — They answer "how do I use this command", which the machine can't answer; probing for "is it installed" would mean searching PATH, for little value.
- 2026-10-14 — Hub commands can name their card (`card:` field, planned in 6.2 of the roadmap); validation checks it, and in the TUI the command opens that card. CLI text is unchanged. — Commands in hubs now lead to their explanation.
- 2026-10-14 — `rsync --delete` (and `--delete-*`) counts as a dangerous command. — It removes files from the destination; the rsync card shows it.
- 2026-10-14 — The disk hub shows `du -sh * | sort -h` instead of `du -sh *`. — Sorted output is what people want, and it links to the sort card.
- 2026-10-14 — First external program: `systemctl` (allowlist of one), for `systemd.status`. It is found through PATH, run with fixed arguments, `LC_ALL=C`, no stdin, a 500 ms timeout (34 ms on the dev VM), and its output is used whatever the exit code. Tests give fixed outputs through `ProbeCtx::with_command`. — Unit states live in systemd's memory: no file holds them, and talking D-Bus would need a new dependency (section 5 allows this case).
- 2026-10-14 — `systemd.overrides` reads /etc/systemd/system directly: drop-ins (`NAME.d/*.conf`), files that replace a packaged unit, local units, and masks (links to /dev/null). Other links (enablement, aliases) are not changes and are left out. — Same answer as `systemd-delta` for /etc, without running it.
- 2026-10-14 — `kernel.sysctl` shows a fixed list of seven telling settings plus every setting written in /etc/sysctl.conf and /etc/sysctl.d/; it serves the sysctl, dmesg and strace cards. — One probe answers "what is set here, and why can't I read dmesg or attach strace".
- 2026-10-14 — Taint flags are decoded from the table in the kernel's "tainted kernels" documentation (bits 0 to 18); unknown bits show as "bit N". — Newer kernels add bits; never crash or guess.
- 2026-10-14 — Chapters 10 (Kernel) and 11 (systemd) are plain chapters, without a hub. — The roadmap's hub list doesn't include them.
- 2026-10-14 — `shell.env` reads /proc/self/environ but only returns an allowlist of ten well-known variables (SHELL, HOME, LANG, EDITOR…) plus a count; `bin.path` only reads PATH, LD_LIBRARY_PATH and LD_PRELOAD. — The environment often holds tokens and passwords, and probe output goes to JSON, MCP and AI prompts. A test checks that a token in the fixture's environment never comes out.
- 2026-10-14 — `shell.startup` and `shell.env` take the login shell and home folder from /etc/passwd (via the uid in /proc/self/status), not from $HOME and $SHELL. — The file says what the account is; the variables may have been changed, and the probe points out a difference.
- 2026-10-14 — `bin.path` lists each PATH folder once, in search order, and groups repeats on one line. — The dev VM's PATH has 27 entries, 13 of them repeats.
- 2026-10-14 — `bin.path` reports which dynamic loaders exist (glibc and musl, x86 and ARM) as "programs this system can run". — It is the live answer to "No such file or directory" for a binary that exists.
- 2026-10-14 — Chapters follow the backlog's order: 12 Libraries & binaries, then 13 Environment & shell, each with its cards in backlog order.
- 2026-10-14 — In the live block, a label wider than its column keeps one space after it. — `XDG_SESSION_TYPE` was glued to its value.
- 2026-10-14 — Chapters 3 (Permissions) and 4 (Processes & scheduling) became hub chapters by pointing SUMMARY.md to the new hubs; their cards keep their numbers. — The roadmap's hub list asks for both; no address changes.
- 2026-10-14 — The `permissions` hub shares its name with an alias of card 3.1: the hub wins and points to the card (the rule from section 7). — "permissions" is first a domain, then a question.
- 2026-10-14 — The `grub` and `systemd-boot` aliases moved from 9.1 to the new 9.3 card. — The more precise card should answer the more precise word.
- 2026-10-14 — Seven last probes: `proc.top`, `proc.cgroup`, `fs.fstab`, `dev.udev`, `net.firewall` (systemctl is-active, already allowlisted), `security.lsm`, `pkg.manager`; `boot.info` now reports the bootloader (systemd-boot's LoaderInfo EFI variable, else a GRUB config) and the unified kernel images. — One live answer per new card where the machine can give one.
- 2026-10-14 — `proc.top` converts CPU ticks with USER_HZ = 100. — It is 100 on every mainstream architecture (x86, ARM); asking sysconf would need a system call per run for no change.
- 2026-10-14 — ACLs/capabilities (3.4) has no probe. — Listing files with ACLs or capabilities means scanning extended attributes across the disk: too slow for a live block.
- 2026-10-14 — Fixed a phase 0 bug: "Run" and the command after it were glued ("Runidk 3.1") in a hub that shares its name with a card. A test now covers it.
- 2026-10-14 — `ProbeCtx` resolves symbolic links inside its root, like a chroot: an absolute target starts again from the root (40 links at most). With the root `/`, paths are used as they are. — Found while running the probes against extracted Debian, Ubuntu and Fedora roots: Fedora's absolute `/etc/nsswitch.conf` link read the host's file. A test now checks that a fixture can never reach the host's files.
- 2026-10-14 — Name check for the `idk` binary (roadmap, naming): no package ships one in Debian sid, Ubuntu 24.04, Fedora (43 to Rawhide), Arch (core and extra file lists) or the AUR. Outside distros, `coalaura/idk` (an AI command helper) installs itself as `/usr/local/bin/idk`, and two smaller projects use the name. — The name is free in distributions but not unique; keeping it is the project owner's call.
- 2026-10-14 — Checked beyond the dev VM: the probes against real Debian 13, Ubuntu 24.04 and Fedora 44 roots (dpkg counts match the status files: 182 and 255); compilation and clippy for x86-64 and 32-bit ARM; the TUI in a real tmux terminal (navigation, prompt, resize to 60×18, quit with exit code 0); `cargo install`.
- 2026-10-14 — The TUI welcome screen aligns its list of hubs. — Seen in a real terminal.
- 2026-10-15 — Demo script in `docs/demo.md`, modelled on the omniscient project's: six acts, each with what to type, what to say and what to check it against; every command was run on the dev VM. A real zombie made with `(sleep 1 & exec sleep 300) &` is the answer key of act 2. — A demo must show checkable facts, not claims.
- 2026-10-15 — Found while writing the demo, fixed: no card ever showed the ⚠ marker (destructive commands only appeared in prose); `find … -delete` and `rsync --delete` are now in their TL;DR code blocks, marked. The exact message "No space left on device" is now an alias of 1.4. — Roadmap 8.1 asks for dangerous commands to be marked; an error message pasted as is should find its card.
- 2026-10-15 — The book has three parts: I How it works (theory: kernel, CPU, memory, storage, GPU, networks), II Your system (the practical chapters), III Shell and commands. SUMMARY.md marks parts with `# Title`, as mdBook does; chapter numbers run on across parts. Part I's six chapters exist now, even empty, so Part II's numbers are final. — Theory and practice in one book rather than two parallel trees: each card already goes practice (TL;DR), this machine (live block), then theory (deep dive), and hubs link both parts.
- 2026-10-15 — Every chapter was renumbered once (free vs available is now 11.1, the old 5.1). This supersedes the phase 0 acceptance line "`idk 5.1` shows free vs available": nothing was published, so numbers were still free to change. From the first release on, new chapters and cards only go at the end of their part or chapter.
- 2026-10-15 — Cards cite each other with `{{card.id}}` (or `{{hub}}`), replaced by the current number when the content loads; validation rejects an unknown id and a hand-written "see N.N". — The 22 hand-written references would all have gone wrong with the renumbering, silently.
- 2026-10-15 — First theory batch: chapter 1 (How the kernel works: what the kernel does, scheduling, virtual memory, interrupts, fork and exec) and chapter 6 (How networks work: OSI and TCP/IP layers, opening a website, IP and NAT, TCP and UDP, Ethernet and ARP). Each card starts from a question and keeps a practical TL;DR; the layers card's TL;DR is a bottom-up troubleshooting checklist. — The rules agreed for Part I: questions, not textbook chapters; what it changes for you first; this machine whenever it can answer.
- 2026-10-15 — Four probes for the theory cards: `kernel.overview` (version, compiler, work since boot from /proc/stat), `kernel.irq` (/proc/interrupts and /proc/softirqs), `mem.vm` (page size, faults, swap traffic, THP mode), `net.layers` (this machine layer by layer: links and ARP neighbours, addresses and gateway, TCP/UDP counters from /proc/net/snmp, DNS). — Theory pointing at the reader's own machine is what sets these cards apart.
- 2026-10-15 — The compiler in /proc/version is read from the second parenthesized group, not from "gcc version": Debian, Ubuntu and Fedora write `(gcc-12 (Debian 12.2.0-14) 12.2.0, …)` or `(gcc (GCC) 14.2.1 …)`. A test covers the four real formats.
- 2026-10-15 — Alias `mac` now means the MAC address (6.5); the SELinux/AppArmor card keeps "mandatory access control". Alias `scheduler` moved from "nice and priorities" to "How the kernel shares the CPUs". — The validation flagged both collisions; the most common meaning wins.
- 2026-10-15 — Hubs list the theory cards of their domain (CPU → scheduler and interrupts, Memory → virtual memory, Network → the five network model cards, Processes → fork and exec). — Hubs are where the two parts meet.
- 2026-10-15 — Second theory batch: chapter 2 (How a CPU works: instructions and architectures, cores and SMT, caches, frequency and power, speculative execution and CPU flaws) and chapter 3 (How memory works: RAM and the memory hierarchy, NUMA, ECC and failing RAM). Card ids use the chapter id as prefix (`hw-cpu.*`, `hw-memory.*`). The TLB and huge pages stay in "How virtual memory works" rather than getting a card. — Same rules as the first batch; no duplicate of what 1.3 already explains.
- 2026-10-15 — Seven hardware probes, all from /proc and /sys: `cpu.features` (architecture, vendor, x86-64 level v1–v4 from the psABI flag lists, notable extensions), `cpu.topology` (sockets, cores, SMT, P/E cores from the cpu_core/cpu_atom PMUs or ARM cpu_capacity, isolated CPUs), `cpu.caches` (grouped by level, type, size and sharing), `cpu.freq` (cpufreq, turbo, cpuidle states, hottest thermal zone), `cpu.vulns` (/sys/devices/system/cpu/vulnerabilities, mitigations=off), `mem.numa` (nodes, distances, local share, numa_balancing), `mem.errors` (EDAC counts, HardwareCorrupted). — Small probes keep each card's live block about its own question. dmidecode (DIMM types and speeds) needs root and a new binary in the allowlist: left out, the card shows the command instead.
- 2026-10-15 — /proc/sys/kernel/arch only exists since Linux 6.1: before that the architecture is inferred from /proc/cpuinfo (`lm` flag on x86, `CPU architecture: 8` on ARM, `isa` on RISC-V). x86 vendor ids are shown as Intel and AMD.
- 2026-10-15 — New fixture `server`: two sockets, two NUMA nodes, ECC controllers with corrected errors and a retired page. The laptop fixture gained a Tiger Lake topology, caches, cpufreq, idle states, thermal zones and vulnerabilities; old-kernel (Raspberry Pi 4) gained its CPU features. — The dev VM has no NUMA, no EDAC and a fixed frequency: only fixtures exercise those paths.
- 2026-10-15 — Third theory batch, which completes Part I: chapter 4 (How storage works: HDD, SSD and NVMe; flash, TRIM and wear; the block layer and I/O schedulers; IOPS, throughput and latency; fsync and durability) and chapter 5 (How a GPU works: what a GPU does differently; kernel, Mesa and NVIDIA drivers; KMS, Wayland and X11; compute and "my program can't see the GPU"). The Disk hub links the storage cards; GPU cards have no hub, as there is no GPU hub. — Each card starts from a question developers actually hit: a slow `dd`, a lost file after a crash, `torch.cuda.is_available()` false.
- 2026-10-15 — Three probes: `disk.hardware` (transport from the device name and the /sys/block link, rotational flag, I/O scheduler, blk-mq queues, write cache, discard, block sizes), `disk.io` (/proc/diskstats since boot: bytes, requests, average ms per request, busy share, cache flushes; Dirty and Writeback from /proc/meminfo; vm.dirty_expire_centisecs), `gpu.devices` (/sys/class/drm cards with PCI vendor and driver, connectors with their status and preferred mode, render nodes, /dev/kfd, NVIDIA module version from /proc/driver/nvidia/version). Disk probes skip loop, RAM, zram, device-mapper and md devices, and empty ones. — No SMART data: it needs root and smartctl or an ioctl; the cards show the commands. USB and virtio disks aren't called "spinning": their rotational flag is unreliable.
- 2026-10-15 — The laptop fixture's /sys/block/sda is now a symbolic link into a USB device path, as on a real system, so transport detection is tested through the root-confined link resolution. The server fixture gained two SATA hard drives, a BMC display (ASPEED, ast) and an NVIDIA compute GPU.
- 2026-10-15 — A GPU hub, chapter 19, at the end of Part II; Part III moves from 19–20 to 20–21 (find is now 21.1). Nothing is published yet, so the "append only" rule doesn't bind; the demo guide and tests follow. — GPUs had four cards and no hub: every other hardware domain has one.
- 2026-10-15 — Part III gains two chapters at its end: 22 Remote work (SSH keys and the agent, ~/.ssh/config and host keys, tunnels, tmux, copying over SSH) and 23 Git (how git stores work, undoing things, merge or rebase, remotes, configuration). — The developer's daily tools after the shell itself.
- 2026-10-15 — Probe `ssh.setup` reads ~/.ssh file names, the type field of .pub files, permission bits, Host counts in ~/.ssh/config, known_hosts and authorized_keys line counts, whether SSH_AUTH_SOCK is set, and sshd's Port, PasswordAuthentication and PermitRootLogin (first value wins, drop-ins read where `Include` appears, `Match` blocks ignored). It never opens a private key, and shows no host names. — Key permissions and sshd's effective settings answer the most common SSH failures.
- 2026-10-15 — Probe `git.config` reads /etc/gitconfig, ~/.config/git/config and ~/.gitconfig (later wins), shows whether user.name and user.email are set but not their values, a fixed list of behaviour settings (pull.rebase, init.defaultBranch, credential.helper…), alias names and the number of includes. — Identity is personal data; behaviour settings explain what git does.
- 2026-10-15 — `ProbeCtx::mode` gives permission bits; fixtures take them from `with_mode`, like space and addresses, since git doesn't keep permission bits and checkouts depend on the umask.
- 2026-10-15 — Destructive git commands are marked dangerous: `reset --hard`, `clean -f`, `push --force` / `-f` / `--force-with-lease` / `+refspec`, `branch -D`, `stash drop|clear`, `checkout -- FILE` and `checkout .`, `restore` without `--staged`, `filter-branch`, `filter-repo`, `reflog expire`. — They throw away work git can't give back, or rewrite history on a shared remote.
- 2026-10-15 — The markdown renderer has no tables: card text uses lists and commented command blocks instead.
- 2026-10-15 — Part I gains chapter 7 (How containers and virtual machines work: what a container is, namespaces, images and overlayfs, VMs and hypervisors, root in a container) and chapter 8 (How programs do several things at once: processes, threads and async; races, locks and atomics; event loops; open-file and process limits; inter-process communication). Parts II and III move by two (free vs available is now 13.1, find 23.1); demo guide, README and tests follow. — The two subjects developers meet most without a model of them; computer science topics with nothing to show on the machine (algorithms, language theory) stay out.
- 2026-10-15 — Probe `virt.detect`: container type from /run/systemd/container, /.dockerenv, /run/.containerenv, /proc/1/cgroup, or a PID namespace of its own; virtual machine from /proc/version (WSL), /sys/hypervisor, DMI vendor and product, the device tree (`*,virt`), or the x86 `hypervisor` flag; namespaces compared with the fixed inode numbers of the host's (pid, user, uts, ipc, cgroup, time; mnt and net have none); /dev/kvm, engine sockets, overlay mounts. — On the dev machine it finds both layers: an LXC container inside OrbStack's VM.
- 2026-10-15 — Probes `proc.threads` (thread counts from field 20 of /proc/PID/stat, threads-max, pid_max), `proc.limits` (/proc/self/limits, fs.file-nr, fs.nr_open) and `ipc.summary` (/proc/net/unix with listening sockets under /run listed first, /dev/shm through statvfs, System V segments, semaphores, queues). New fixture `container`: a Docker container on an EC2 VM.
- 2026-10-15 — Part I gains four chapters at its end: 9 How filesystems work (layout, journaling, copy-on-write, choosing one, the VFS), 10 How time works (wall and monotonic clocks, NTP, time zones, Unix time and 2038), 11 How cryptography works (hashes, encryption and signatures; public keys; certificates; random numbers; disk encryption), 12 How text is stored (UTF-8, locales, line endings and invisible characters). Part II gains a Logs hub (26: journalctl, where logs go, rotation, logging from programs). Part II moves by four, Part III by five (free vs available is 17.1, find 28.1). — The rest of the list agreed after the container and concurrency chapters.
