# Decisions

Decisions taken during development that ROADMAP.md does not cover, one line each: date, decision, reason.


- 2026-10-14 — SUMMARY.md order is Filesystem, Disk, Permissions, Processes & scheduling, Memory, Finding and transforming. Filesystem and Permissions have no cards yet. — The phase 0 acceptance (`idk 5.1`) and the TUI mockup put Memory at chapter 5; the section 6 example would make it 3.
- 2026-10-14 — In SUMMARY.md, a hub can only be a chapter page and a card can only be an entry under a chapter; the titles in SUMMARY.md must match the frontmatter titles. — Stops the TOC and the cards from drifting apart.
- 2026-10-14 — `probes::REGISTRY` lists probe names (with no functions) from phase 0. — The 6.3 validation must check probe names before the probes exist; the functions come in phase 1.
- 2026-10-14 — Kept `serde_yaml` 0.9 although it is deprecated upstream. — The roadmap names it and it works. Switch to a maintained fork if it causes trouble.
- 2026-10-14 — Content uses fenced code blocks (```), never indented ones. — In CommonMark, an indented block right after a list becomes a paragraph of the last list item.
- 2026-10-14 — TL;DR length = non-blank source lines, code fences excluded. — Close to what the screen shows, and cheap to check.
- 2026-10-14 — Validation beyond 6.3: unknown frontmatter fields are errors, and an alias can't be a subcommand name (`toc`, `search`…) or look like a chapter number. — Catches typos and keys that could never be reached.
- 2026-10-14 — `idk 5` (a bare chapter number) opens that chapter's hub when it has one, and otherwise matches nothing. — Natural extension of resolution step 3.
- 2026-10-14 — The no-match message suggests `idk toc` until `search` and `ask` exist. — Never point users to a command that isn't there yet.
- 2026-10-14 — Exit code 3 = internal error (invalid embedded content, failed write to stdout); a closed pipe is not an error. — 0/1/2 are taken by success, no match and usage error.
- 2026-10-14 — `build.rs` with `rerun-if-changed=content`. — `include_dir!` does not see new files without it.
- 2026-10-14 — A hub page lists its own chapter's cards first, then its `cards` field. — Otherwise the Memory hub would not link to 5.1.
- 2026-10-14 — Text width = number of chars, without `unicode-width`. — Content is mostly ASCII; avoids a dependency.
- 2026-10-14 — Added `libc` for `statvfs` (one small `unsafe` call). — std has no statvfs; `nix` or `rustix` would be much bigger for a single call.
- 2026-10-14 — Added `serde_json` (JSON output) and `insta` (snapshots, dev only). — Both listed in section 4.
- 2026-10-14 — `ProbeCtx` takes filesystem space from a fixed table in tests instead of statvfs. — statvfs on a fixture dir would return the host's numbers, and snapshots would change from machine to machine.
- 2026-10-14 — `disk.tree` matches mounts by device number, or else by source path (`/dev/vdb1`, `/dev/mapper/NAME`). — btrfs subvolumes report an anonymous device number (0:NN), as on the dev VM.
- 2026-10-14 — `disk.tree` hides loop and ram devices and devices of size 0, and says how many it hid. — Snaps and container tools create dozens of them.
- 2026-10-14 — buff/cache = Buffers + Cached + SReclaimable. — Same formula as procps-ng `free`; checked against `free -k` on the dev VM.
- 2026-10-14 — Rotational disks are shown as "rotational", not "HDD". — Virtual disks often report rotational=1; "HDD" would be wrong there.
- 2026-10-14 — Fuzzy matching: edit distance with transpositions on ids, aliases and titles; allowed distance 1 (≤4 letters), 2 (≤8), 3 beyond, plus typed prefixes; nothing under 3 letters. The closest page is shown with a note. — `memroy` → Memory, while a random short word doesn't open a random page.
- 2026-10-14 — When nothing matches, the suggestions come from `search` (which tolerates one typo in words of 5+ letters). — `idk swapiness` then points to Memory and 5.1.
- 2026-10-14 — `--json` works on every command (`toc`, `search`, `probe`), not only on queries. — Cheap, and the MCP server (phase 4) needs the same structures.
- 2026-10-14 — `idk probe` without a name lists the probes. `idk search` without a match exits with 1, like a query. — Discoverability; consistent exit codes.
- 2026-10-14 — `view::Lookup` (query, match kind, entry, suggestions, probe results) is the view model shared by text, JSON and later surfaces. — Section 5 data flow.
- 2026-10-14 — Pages are built as a `render::Doc` (lines of styled spans, some with an `Open` or `Toggle` action); the CLI turns it into ANSI text, the TUI into widgets plus click regions. — The only way to share the renderer without duplicating it (phase 2 criterion). All CLI snapshots stayed byte-for-byte identical through the change.
- 2026-10-14 — `ratatui` 0.30 without default features (`crossterm` only), and crossterm through `ratatui::crossterm`. — Fewer dependencies, and one crossterm version.
- 2026-10-14 — TUI keys: ↑↓/jk move or scroll, ←→/hl switch pane, Tab/Shift-Tab go from link to link, Enter opens, Backspace goes back, `/` search, `?` prompt, `r` refresh, `M` mouse, `q` quits, Esc closes an overlay or quits. — The roadmap mockup gives j/k, enter, /, r, ?; Tab for links works like a browser.
- 2026-10-14 — In the TUI, deep dive questions show collapsed (▸); opening one scrolls it to the top of the pane. — Otherwise a question at the bottom opens off screen.
- 2026-10-14 — The TUI's left column adapts: tables put a long command on its own line when the pane is narrow (`MAX_LEFT` = min(30, width/3)). — At 80×24 the content pane is 52 columns; CLI output is unchanged.
- 2026-10-14 — `idk` alone opens the TUI only when stdin and stdout are terminals; otherwise it prints the help and exits with 2. — Scripts and pipes keep the phase 0 behaviour.
- 2026-10-14 — `idk ask` builds the prompt even when nothing matches (system data only) and says so on stderr. The arch comes from the build target (`std::env::consts::ARCH`). — A question without a card is still worth asking.
- 2026-10-14 — `--redact` replaces the home directory with `~`, any other `/home/NAME` with `/home/<user>`, and the hostname and username (whole words only) with `<hostname>` / `<user>`. It applies to the whole prompt, the user's question included. — Probe data (mount points, process names) and the question can both leak them.
- 2026-10-14 — The TUI's `?` shows the prompt for the current page without redaction; `M` frees the mouse to select it. — No clipboard access without a new dependency.
- 2026-10-14 — Phases 2 and 3 are one commit. — The TUI's `?` key (phase 3) and the prompt builder were written together.
- 2026-10-14 — MCP with `rmcp` 3.5 (features `server`, `transport-io`, `macros`) and `tokio` on a single-thread runtime, started only by `idk mcp`. — Section 4 names rmcp; the rest of `idk` stays synchronous.
- 2026-10-14 — Every MCP tool returns its JSON as text content, with the same shapes as `--json` (`view::Lookup`, search hits, `ProbeResult`). — One structure per answer whatever the surface.
- 2026-10-14 — MCP: `lookup` with no match is a normal result (`"match": "none"` plus suggestions); an unknown probe name is a tool error (`isError`) that lists the valid names. — An agent can recover from both without a protocol error.
- 2026-10-14 — Every tool carries `readOnlyHint: true` and `openWorldHint: false`, and its description says "Read-only". — Section 8.4: the server must state that it never modifies the system.
- 2026-10-14 — `idk toc --json` now prints `view::Toc` (hubs, then chapters with card references) instead of the raw `Chapter` list. — Same output as the MCP `toc` tool, and the cards come with titles.
- 2026-10-14 — New chapters go after the existing ones (7 CPU, 8 Network, 9 Boot), and new cards after the existing cards of their chapter. — Chapter numbers are addresses people type (`idk 5.1`): adding content must not renumber what exists.
- 2026-10-14 — Seven new probes: `cpu.summary`, `net.interfaces`, `net.listening`, `net.dns`, `boot.info`, `user.identity`, `fs.tmp`. — Each answers the question of a new card or hub on the machine (phase 5 rule).
- 2026-10-14 — IP addresses come from `getifaddrs` (libc), replaced by a fixed list in tests like `statvfs`; no file in /proc lists IPv4 addresses per interface. — Without them the network hub would miss its main answer.
- 2026-10-14 — `net.listening` finds a socket's process through /proc/PID/fd links, so other users' processes show only as root; the note points to `sudo ss -tulpn`. — Read-only, no external binary, honest about the limit.
- 2026-10-14 — Firmware is reported as UEFI (/sys/firmware/efi), device tree (ARM boards and VMs) or BIOS; Secure Boot comes from the SecureBoot EFI variable (fifth byte). — The dev VM is ARM with a device tree: "BIOS" would have been wrong there.
- 2026-10-14 — `FsSpace` now carries inodes (statvfs `f_files`/`f_ffree`); the disk table shows inode use when the filesystem counts inodes (not btrfs). — Needed by the "Links, inodes and disk full" card.
- 2026-10-14 — The live block's label column is 10 wide instead of 9. — "Firmware" and "Governor" left a single space before their value.
- 2026-10-14 — Word wrap cuts a non-code word longer than a whole line (a kernel command line token on the dev VM was 88 characters); code is still never cut. — Keeps the 80-column rule on real machines.
- 2026-10-14 — Search excerpts prefer the card's text (TL;DR, pitfalls, deep dive) over its commands and paths fields. — "swapon vmstat" told less than the TL;DR line.
